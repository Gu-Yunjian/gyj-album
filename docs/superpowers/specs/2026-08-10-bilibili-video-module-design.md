# B 站视频模块设计

## 目标

为摄影站增加独立的视频页。管理员在本地后台维护多条“标题 + B 站链接”，访客可在站内使用 B 站原生播放器观看。导航顺序调整为“画廊 / 影集 / 视频 / 关于”。

项目继续使用静态部署。视频功能不增加播放器依赖，不代理或解析 B 站媒体流。

## 采用方案

前台直接嵌入 `player.bilibili.com/player.html`。该方案与 MIT 项目 [`zeffon/bilibili-embed-renderer`](https://github.com/zeffon/bilibili-embed-renderer) 的实现路径一致，但项目自行实现小型 TypeScript 组件，避免依赖已归档的软件包。

不采用 DPlayer、ArtPlayer 或视频流解析服务。这些播放器需要 MP4、HLS 或 DASH 地址，无法直接使用普通 B 站视频链接。解析真实媒体流还会增加接口失效、跨域、鉴权和部署成本。

## 数据模型

视频配置保存在 `public/content/videos.json`：

```json
{
  "videos": [
    {
      "title": "视频标题",
      "url": "https://www.bilibili.com/video/BVxxxxxxxxxx/"
    }
  ]
}
```

数组顺序即前台顺序，不存储额外排序字段。后台保存 `b23.tv` 短链前先将其解析为标准 B 站地址，因此静态页面不依赖短链跳转。

## 链接处理

纯函数 `parseBilibiliUrl` 负责解析：

- `https://www.bilibili.com/video/BV...`
- `https://www.bilibili.com/video/av...`
- B 站播放器链接中的 `bvid` 或 `aid`
- 多 P 视频的 `p` 或 `page` 参数

本地后台通过一个小型 API 解析 `b23.tv`。API 只接受 `b23.tv` 主机，并校验最终跳转地址属于 `bilibili.com`，防止后台替任意 URL 发起请求。普通长链不访问网络。

解析成功后，播放器组件只接收规范化的 `bvid` 或 `aid` 和分 P 页码。组件生成 HTTPS iframe 地址，并设置 `loading="lazy"`、全屏权限、高清参数和默认关闭弹幕参数。

## 前台页面

新增 `/videos` 静态页面和 `VideoCard` 组件：

- 页面沿用现有白底、黑色文字、细边框、导航栏和间距变量。
- 页头显示“视频”，不增加宣传文案。
- 桌面端使用双列 16:9 播放卡片，窄屏改为单列。
- 卡片标题位于播放器下方。
- 每个播放器下方提供“在 B 站观看”链接，作为第三方播放器加载失败时的备用入口。
- 配置为空或缺失时显示克制的空状态，页面仍可静态构建。

## 后台管理

`/admin` 增加“视频管理”标签页。该页面沿用现有后台控件样式，提供：

- 标题和 B 站链接输入框
- 添加视频
- 上移、下移和删除
- 保存到 `public/content/videos.json`

标题和链接均为必填项。后台拒绝非 B 站链接、无法解析的链接和重复视频。保存成功后提示管理员提交并部署静态文件。

后台仍是本地内容工具，不增加线上登录、数据库或远程 CMS。

## 错误处理

- 链接格式错误：后台在加入列表前显示具体原因。
- 短链解析失败：保留输入内容，提示改用完整 B 站链接。
- 配置文件缺失或 JSON 无效：前台记录错误并显示空状态，构建不中断。
- 单条历史数据无效：页面跳过该条并记录错误，其余视频继续显示。
- iframe 加载失败：浏览器无法可靠读取跨域 iframe 错误，页面始终提供外部观看链接。

## 测试与验收

自动化测试覆盖：

- BV、AV、播放器链接和分 P 参数解析
- 非 B 站链接与畸形标识拒绝
- 播放器 URL 参数生成
- 空配置和无效条目过滤

验收时运行 lint、测试和生产构建，并在浏览器检查：

- 桌面端双列和移动端单列布局
- 导航顺序及 `/videos` 路由
- 后台添加、排序、删除、保存和刷新后回读
- B 站播放器播放、全屏及外部观看链接

## 范围外事项

- 下载、代理或缓存 B 站视频文件
- 自定义弹幕、清晰度或播放进度同步
- 自动读取 B 站标题、封面、作者或播放量
- 线上可写 CMS
